- `npm run build`: Next.js 16.4.6 وTypeScript، نجح البناء.
- `npm test`: ثلاثة اختبارات نجحت: كلمات عربية/إنجليزية، حفظ الفقرات الفارغة، وإنتاج TXT/MD/DOCX/EPUB ثم فك الملفات وقراءة النص الفعلي وXML escaped وEPUB mimetype.
- `NODE_USE_ENV_PROXY=1 node tests/rls-run.mjs`: 32 تحققًا ناجحًا على Supabase الحقيقي عبر المفتاح العام وجلسات مستقلة. SELECT/UPDATE/DELETE ومنع نقل المالك وربط كتاب بمشروع الغير، رفض save قديم أو غير مملوك، ومنع تنزيل ملف مستخدم آخر. النتائج في rls-results.json.
- `npx playwright test tests/core.spec.ts`: مسار متصفح Chromium ناجح: دخول، رواية/كتاب/فصل، نص 23940 حرفًا (نحو 4680 كلمة)، حفظ، تركيز، خروج ودخول واسترجاع، شخصية، حدث وتغيير حالة، لقطات Desktop/iPad/Phone، عدم overflow أفقي، reduced-motion. صفر pageerror في هذا المسار.

## التشغيل التجميعي الأخير

## أخطاء اكتُشفت وأُصلحت
- package.json كان commonjs مع ES imports؛ صُحح إلى module.
- بعد الدخول مجددًا كان يمكن إعادة استخدام مشهد قديم فارغ قبل اكتمال تحميل البيانات؛ النص كان محفوظًا في DB. صُحح فصل حالة التحميل وتحديث scene عند نجاح الحفظ، ثم أعيد المسار ونجح.
- Vitest التقط ملفات Playwright؛ فُصلت مجموعتا الاختبار عبر include **/*.test.ts، وأعيدت اختبارات الوحدات بنجاح.
- خلفيات لوحات الهاتف أصبحت معتمة، وفتح إحداها يغلق الأخرى.

## حدود التحقق
تسجيل حساب مستخدم جديد عبر SMTP محجوب حاليًا بـ email rate limit exceeded، مع mailer_autoconfirm=false. أول عناوين QA الاصطناعية رُفضت. وُفر حسابان مؤقتان إدارياً في Auth لاختبار الجلسات الحقيقية، دون تغيير التأكيد أو SMTP ودون حفظ كلمات مرور في المستودع. لذلك لا يُعد إنشاء الحساب وتأكيده أو استعادة البريد end-to-end ناجحًا.

اختبارات recovery.spec.ts: **2 passed (23.5s)**. انقطاع شبكة، تنبيه فشل الحفظ، بقاء المسودة، إعادة تحميل واستعادة، استعادة نسخة قديمة، وتعارض تبويبين مع إثبات بقاء النص الأحدث. فشل التشغيل الأول لأن locator افترض شكلًا واحدًا للأرقام؛ صُحح ليقبل أرقام locale دون تخفيف التأكيد على النص المستعاد.

اختبار publish.spec.ts: **1 passed (6.7s)**. كلمة مرور خاطئة ورسالة عربية، إنشاء وتحرير ملاحظة، تنزيل EPUB من الزر وفك ZIP للتحقق من النص، استيراد Markdown بعد معاينة، وإضافة مشهد. كشف التشغيل الأول التباس اسم textarea في وضع التحرير؛ أضيف aria-label صريح وأعيد الاختبار بنجاح.

# الاستجابة
Desktop >1100px: فصول يمين 240px، محرر مرن، سياق يسار 248px. >1500: 270/مرن/280. Laptop/iPad ≤1100: السياق لوحة عائمة قابلة للإغلاق، الفصول 210px. iPhone ≤760: النص بعرض الشاشة، اللوحات overlays، ملاحة سفلية زجاجية، padding للوحة الملاحة. عرض المخطوطة محدود مستقل عن خط الواجهة. vh ديناميكي d vh للمحرر. CSS logical properties للحدود والحشوات.

أحجام التحقق: desktop، iPad 810×1080 و1080×810، هاتف 390×844. محاكاة المقاس لا تثبت أداء A10 أو Safari على iPad حقيقي. لوحة المفاتيح الافتراضية والأداء الفيزيائي غير متحققين. بعض أدوات الترتيب صغيرة وتحتاج تكبيرًا لمسياً قبل قبول وصول شامل.

## إصلاحات v2
writing-view flex بارتفاع 100dvh، الشريط والbanner لهما ارتفاع طبيعي، layout يأخذ المساحة المتبقية، فلا يتسبب banner الضيف في تمرير صفحة المحرر. drawers على iPad/Phone absolute داخل layout، لا top ثابت يتجاهل ارتفاع banner. شريط أدوات اللوحات أعلى ترتيبها حتى يمكن إغلاقها.

V3: صفحة الرواية عند 1440 و1080 و810 و390 عرضًا. هامش 20px على الهاتف، غلاف أصغر، تبويبات بتمرير داخلي عند الحاجة، بطاقة القصة أسفل الفصول، حد شريط التنقل السفلي 12px من الجانبين. جرى فحص document.scrollWidth <= innerWidth والتقاط الصور فعليًا. لا تُعد محاكاة مقاس iPad تحققًا من Safari/A10 الفيزيائي.

## V4
Profile 1440/1080/810/390 مختبر بلا overflow، الصورة متداخلة والغلاف يقص object-fit:cover، الروابط تلف والاسم يقبل الكسر. رف عمودان على الهاتف، أربعة في شاشة واسعة. تبويبات الاكتشاف والأنواع scroll أفقي مقصود داخل العنصر، دون توسيع الصفحة. أدوات المحرر تلف إلى صفوف وتبقى اختيار الخط متاحًا عند إخفاء اللوحتين. القارئ يحمل فصلًا واحدًا لتجنب جميع أجسام الرواية في الذاكرة. هذه اختبارات Chromium، وليست اعتمادًا لجهاز A10/Safari.

# الأمان
لا service_role ولا كلمة مرور في الواجهة أو جداول التطبيق. Publishable Key فقط. Supabase SDK يدير الجلسة والتجديد، وجميع طلبات البيانات تحمل JWT مع RLS. user_metadata لا تستخدم في أي صلاحية. الحماية الفعلية في القاعدة وتعمل حتى مع طلب REST مباشر.

RLS: ملكية auth.uid()، منع نقل المالك، وربط مركب يمنع إلحاق بيانات بحاوية مستخدم آخر. Storage private مع سياسات select/insert/update/delete على uid في المجلد الأول. السجل القديم محفوظ قبل كل تعديل مقبول.

React يهرب النصوص؛ لا dangerouslySetInnerHTML. Tiptap يعرض schema محددة، استيراد DOCX كنص فقط، وEPUB XML يهرب الرموز. رؤوس nosniff وframe DENY وReferrer Policy وPermissions Policy. CSP شاملة لم تُنفذ. التحقق من أحجام JSON والطول والتدقيق المتقدم يحتاج تحسينًا. بيانات الاستعادة المحلية ليست مشفرة؛ الجهاز المشترك يتطلب انتباهًا، وتُعزل المفاتيح حسب uid.

Security Advisors: لا تحذير على جداول أو دوال مِداد. تحذيران informational عن جداول zeus_ بدون سياسات (تُترك دون تدخل)، وتحذير عام Leaked Password Protection Disabled؛ يحتاج ضبط Auth مناسبًا للمشروع المشترك. لا ندعي خلو المشروع بأكمله من التحذيرات.

اختبارات RLS الفعلية في docs/rls-results.json. مستخدما QA مؤقتان جرى توفيرهما في Auth بصلاحية إدارية بسبب حد البريد؛ الدخول والبيانات اختُبرت كـauthenticated بالمفتاح العام، لا كـpostgres. هذه ليست برهانًا على تسليم رسالة تأكيد البريد.

## التسجيل المباشر والضيف — الإصدار الثاني
وفق طلب المستخدم، إنشاء حساب مِداد لا يحتاج تأكيد بريد. Edge Function midad-signup تستخدم email_confirm:true على الخادم؛ هذا لا يثبت ملكية البريد، وهو سلوك مقصود. لم تُعطّل سياسة المشروع المشتركة لتطبيقات أخرى. النهاية عامة لأنها تنشئ مستخدمًا، مع تقييد methods/origins وحجم الطلب، وحدود IP/email hashes، ولا تعيد مفاتيح أو تسجل كلمات مرور. خدمة Auth تخزن كلمة المرور وحدها. rate SQL غير قابلة للاستدعاء من authenticated أو anon.
لا يُقبل من العميل user_id أو role أو app_metadata في signup. بيانات الضيف في IndexedDB، دون صلاحيات أو افتراض جلسة. النقل للحساب يستخدم JWT المستخدم الحالي وRLS المعتادة.
النسخ الاحتياطية لا تضم passwords أو tokens أو صور Storage؛ تحتوي أعمال المستخدم فحسب. استعادة backup تتحقق من روابطه وتولّد UUIDs جديدة.

## V3: المشاركة والقراءة وربط ChatGPT

المشاركة لا تمنح الوصول للملاحظات أو عالم الكاتب أو التخطيط. القارئ يرى الفصول الأصلية فقط، والكاتب المشارك يعدّل الفصول مع بقاء user_id للمالك. trigger يمنع تغيير الملكية. النشر العام يمر عبر جدول مخصص لفصول يختارها المالك، وتستبعد واجهات القراءة المسودات البديلة والملاحظات.

تحذيرات Security Advisor المتعلقة بدوال SECURITY DEFINER مقصودة ومراجعة: دالتا القراءة العامة تعيدان فقط بيانات الفصول المنشورة؛ دوال الموافقة مقيدة بـ auth.uid() ورمز عشوائي أحادي الاستخدام؛ دالة البحث عن صديق تعيد الاسم ومعرّفه بالاسم الدقيق ولا تعرض البريد أو نبذة ملف خاص. search_path فارغ. كل وظائف الكتابة الآلية وخريطة الهوية متاحة لـ service_role فقط. لا جداول midad_* بلا RLS.

تبقى تحذيرات المشروع المشترك الخاصة بـ zeus_* وحماية كلمات المرور المسرّبة إعدادات منفصلة لم تُعدّل ضمن هذا العمل. مرجع التحذير المقصود: https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable .
